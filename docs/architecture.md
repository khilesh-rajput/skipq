# Architecture and business rules

The browser never supplies identity, role, unit prices, total, or payment status as authoritative values. JWT identity is validated by middleware. Registration creates only `student`; staff access is scoped through `staff_canteens`; admin routes require `admin`.

Order transaction: lock active canteen, exact slot, then each ordered menu row; validate slot date/open hours, item availability, stock, and `sum(preparation_minutes ? quantity) <= capacity_minutes - reserved_minutes`; calculate amount from locked current prices; insert order and snapshot lines; decrement stock and increment reserved workload; commit. Concurrent requests serialize on the same slot/item rows. Cancellation before preparation reverses stock and workload. Pickup codes are bcrypt hashes and verification locks the order for single-use consumption.

Request path: React Router page ? Axios API client ? Express JSON parser/security middleware ? JWT/role checks ? Zod validation ? service ? prepared MySQL queries/transaction ? consistent `{ok,data}` response. Razorpay webhook raw bytes are handled before JSON parsing and event ids are unique for idempotency.

## Known academic scope

Slots are seeded for seven days and should be regenerated by a scheduled task in long-running deployments. Slot reservation uses total prep minutes as a simple workload proxy. Refund handling, password reset, refresh tokens, review UI, and complete menu/category CRUD UI are outside this demonstration's current server surface. The manager can update item inventory/availability through direct SQL; core customer checkout and order workflow are implemented. Payment mode requires actual provider test credentials for online verification.
